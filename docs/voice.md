# FateVerse 文案語氣規格（Voice Spec）

> 適用範圍：所有**使用者可見的解讀文字**——`src/engines/**` 的模板字串與內嵌文案表、`src/data/**` 的靜態內容、`public/data/**` 的 JSON 文案，以及 `src/components/**` 內嵌的說明文字。
> 本文件同時是人類撰稿準則，也是 `npm run test:specificity` 的機器檢查依據。
> 建立日期：2026-07-25。

## 為什麼需要這份規格

FateVerse 的定位是「一面鏡子，不是一本預言書」，站內還有一個**巴納姆效應鏡子**模組，專門教使用者辨識冷讀術話術。如果我們自己的解讀文案就是巴納姆句，這個定位會自我矛盾——使用者在鏡子模組學會的拆解方法，回頭就能拆掉我們的報告。

實際回饋也指向同一個問題：目前文案多是「變數插值進模板」，句子為了對所有輸入都成立，寫成了「你可能傾向於…」這種對誰都成立的敘述，讀起來「不夠擬人化、像說明書」。

---

## 核心判準

> **一句解讀必須有可能說錯。**
>
> 判定方法：把命盤換成另一個人。如果那句話**仍然成立**，它就不是在描述這個人，不合格。

這條凌駕以下所有細則。細則是為了讓這個判準可操作、可被機器檢查。

---

## R1. 第二人稱用「你」，禁用「您」

**規則**：全站一律「你」。「您」帶來服務業距離感，與鏡子定位不符。

**機器檢查**：文案中出現「您」即違規。

**現況**：repo 全域掃描 0 次，目前完全合規。此規則為**防迴歸**用。

```
✗ 您的日主為甲木，建議您留意合作關係。
✓ 你的日主是甲木。
```

---

## R2. 現在式陳述優先，避免未來斷言

**規則**：描述當下的結構與傾向，不預告尚未發生的事。命理計算能算出盤面，算不出未來事件。

**機器檢查**：出現「將會」「必定」「注定」「終將」「一定會」等未來斷言詞即違規。

```
✗ 三月之後你的事業將會出現轉機。
✓ 大運在 2027 年換柱，從壬午轉為癸未。換柱前後那一兩年，是回頭檢查現在的節奏還合不合用的時機。
```

第二句仍然講未來，但講的是**可查證的曆法事實**（換柱年份）與**行動建議**，不是斷言結果。

---

## R3. 每個段落至多 3 句

**規則**：一段最多 3 句（以「。」「！」「？」計）。長段落會稀釋具體性，也讓讀者失焦。

**機器檢查**：單一文案欄位切句後 > 3 句即違規。

**repo 實例**（`src/engines/fallback-report.ts` 的 `sections.bazi`，現為 5 句）：

```
✗ 你的日主為甲（木），四柱為甲子、丙寅、庚午、壬申；月支寅屬春令，以季節來看你的日主五行屬「旺」，
  另外找到 3 組合、沖、刑、害等干支關係。胎元丁巳、命宮辛未、身宮癸酉；節氣參考為立春。
  藏干、十神與大運都幫你排好了；完整的日主強弱與喜用神綜合判讀在八字分頁，採公開的計分規則，
  與各流派手工論命可能不同。

✓ 你的日主是甲木，生在寅月——春天的木，正當旺。
  四柱裡有 3 組刑沖合害，代表這張盤的張力不在單一柱上，而在幾組關係之間。
  （其餘結構資料移到資料欄位呈現，不寫進解讀段落。）
```

## R4. 模糊限定詞全篇至多一次

**規則**：「可能／或許／傾向於／往往／有時」這五個詞，**整份報告合計至多出現 1 次**。

限定詞是巴納姆句的主要載體：加上「可能」，任何句子都變成不可能說錯，也就違反核心判準。真正需要保留不確定性的地方，用**條件句**取代限定詞——說清楚「在什麼情況下」，而不是模糊掉整句。

**機器檢查**：五個詞在一份報告內合計出現次數 > 1 即違規。

**現況**：`src/` 與 `public/data/` 全域「可能」98 次、「容易」61 次、「傾向」11 次、「有時」8 次、「往往」5 次。這是目前最大的違規來源。

**repo 實例**（`src/engines/zodiac-engine.ts` 的 `blindSpots`）：

```
✗ 可能較固執        → ✓ 決定之後很難改，即使拿到新資訊也一樣
✗ 容易過度思量      → ✓ 同一個決定會反覆推演到錯過時機
✗ 節奏可能太快      → ✓ 別人還在確認細節時，你已經開始動手了
```

---

## R5. 具體名詞優先於抽象形容詞

**規則**：寫**可觀察的場景**，不寫**性格標籤**。標籤無法否證，場景可以。

判斷方法：這句話能不能拍成一個畫面？不能，就太抽象。

**repo 實例**（`src/engines/numerology-engine.ts` 的 `CONTENT`）：

```
✗ 生命靈數 2 關注關係與平衡，擅長看見互動中的細節。
✓ 一群人講話時，你會先注意到那個沒開口的人。
```

```
✗ 生命靈數 7 傾向深入理解，珍惜獨處與知識上的真實。
✓ 別人問你「這個好不好」，你會想先弄清楚它是怎麼運作的才回答。
```

**repo 實例**（`src/data/interpretation-library.ts` 的 `TEN_GOD_LIBRARY.比肩`）：

```
✗ 可觀察自己如何在合作中保留主體性，也留意競爭是否遮住共同目標。
✓ 合作時你會先確認哪一塊是你負責的，那塊不太願意讓人插手。
```

---

## R6. 免責與專業邊界維持現行規範

**規則**：語氣調整**不得**放寬既有的醫療／法律／投資邊界。

以下必須維持：

- 報告尾端的 `cautions`（「僅供文化探索、娛樂與自我反思」「重大醫療、法律、投資或人生決策，請依實際證據並諮詢合格專業人士」）。
- 健康主題必附就醫提醒。
- 財務主題不得出現具體投資建議或收益暗示。
- 籤詩與命盤資料的 `dataSource` 分層標註（哪些是傳統原文、哪些是 FateVerse 解讀）不得移除。

**注意**：R4「限定詞至多一次」**不適用**於免責聲明。免責文字的保守措辭是法律與倫理需要，機器檢查會排除 `cautions` 欄位與健康／財務提醒句。

---

## R7. 不用對沖語

「可觀察到 X 的傾向」這種句子把所有斷言都洗掉了——**換成任何一張命盤都成立，所以它不可能說錯，也就不可能讓人覺得被說中。** 命中感的前提是那句話有風險。

| ❌ | ✅ |
|---|---|
| 可觀察到「觀察敏銳」與「可靠」並存的傾向 | 「觀察敏銳」和「可靠」在你身上會一起出現 |
| 正向面可參考觀察敏銳、資源整合 | 你的強項在觀察敏銳、資源整合 |
| 適合拿來檢查目前是否只使用熟悉能力 | 拿這件事檢查一個問題：最近是不是只用了自己順手的那幾招 |
| 可發揮組織、決斷 | 你擅長組織、決斷 |

這條和 R4 不同：R4 抓的是單一模糊副詞（可能／或許／往往），R7 抓的是整個「不敢下判斷」的句型。

---

## R8. 不在解讀句裡解釋自己

免責與方法說明放在固定的一處（`Disclaimer` 元件、方法說明區塊），不是每句都放。在解讀句裡講「這是文化模型的線索」，等於一邊表演一邊解釋魔術怎麼變的。

| ❌ | ✅ |
|---|---|
| 這些是文化模型的自我反思線索，不是固定命運 | 這是看自己的一個角度，不是命定的結論 |
| 生命靈數所強調的「組織」，可和生肖的「資源整合」交叉參照 | 生命靈數說你「組織」，生肖說你「資源整合」——兩邊在講同一種能力 |
| 本次計算結果為 8，可發揮組織、決斷 | 你的生命靈數是 8，擅長組織、決斷 |

---

## R9. 書面語換成日常講法

這些詞不算錯，只是不會有人講話這樣講。換掉之後意思不變，但讀起來從報告變成人在跟你說話。

並存 → 一起出現；著重 → 比較看重；象徵為 → 說的是；較為 → 比較；之處 → 的地方；顯示出 → 看得出；具有 → 有；此類 → 這類；亦 → 也；予以／加以 → 直接刪掉。

**刻意不列入**：「其中」「方面」形上很像論文腔，但日常對話用得極頻繁（其中一個、另一方面）。列進來只會製造假陽性，逼撰稿人繞路寫出更不自然的句子——這一軸的價值在於誤報要夠低，否則大家會學會忽略它。

完整標記表與例外清單見 `tests/specificity/plainness.ts`。

## 判準的適用範圍：解讀 vs 框架文字

核心判準（「換個命盤還成立就不合格」）只適用於**對這個人的解讀**。報告裡還有另一類文字，它們**本來就該對所有人成立**：

| 類別 | 例子 | 是否適用出現率判準 |
|---|---|---|
| **解讀**（interpretation） | 「四柱裡火最多，代表你自然而然就會用火的方式做事」 | ✅ 適用 |
| **框架文字**（framing） | 方法說明（「把各系統翻譯成同一種語言再比較」）、免責提醒（「實際的職涯決定請以能力、市場和你的意願為主」）、資料標籤（「留意：容易分心」「生肖（子支）」） | ❌ 不適用 |

把免責聲明拿去套「必須有可能說錯」的標準是荒謬的——免責聲明的價值正在於它永遠成立。工具因此把兩者分開：framing 標為 `FRAMING` 不計分，只有 interpretation 會被判 `OVER_GENERIC`。

分類定義在 `tests/specificity/extract-sentences.ts` 的 `FRAMING_FIELDS`。**未列出的欄位一律視為 interpretation**，確保新增欄位預設受最嚴格檢驗；要放進白名單必須明確加入並附理由。

## 量測涵蓋範圍

`npm run test:specificity` 分兩條路檢查，合計約 4,000 條靜態文案加上 500 份完整報告：

| 路徑 | 涵蓋內容 | 判準 |
|---|---|---|
| **報告管線**（命盤驅動） | 綜合報告、融合解讀、整合剖面、系統結論、時間軸 | 出現率（OVER_GENERIC／WATCH／OK）＋ R1–R4 |
| **靜態語料**（非命盤驅動） | 塔羅牌義、決策儀式卡、八字十神／行星／星座／宮位／相位／紫微星曜與宮位解讀庫、今日指引、六十甲子籤與觀音一百籤的白話解讀 | 只套 R1／R2／R4（固定文本無出現率可言） |

報告管線另外套 **R7–R9 口語度**，以句子模板為單位計數，framing 不計。

**防迴歸已啟用**：

- 靜態語料違規上限 **0**——新增任何含「您」、未來斷言或模糊限定詞的文案都會讓測試失敗。
- 報告管線採「棘輪」：`OVER_GENERIC` 上限釘在目前水準（37）而非 0。剩餘項目多為結構性句框（每張命盤都有最強／最弱五行，該句框必然出現），要再降需改報告結構而非文字。改善後請同步調低預算。
- 口語度（R7–R9）上限 **0**。標記表刻意只收高信心的詞，誤報低才守得住 0；真有正當理由要用某個詞，請加進 `plainness.ts` 的 `EXEMPTIONS` 並寫明原因，不要調高預算。

籤詩詩句、`story`、`dataSource` 與 `cautions` 依白名單排除——傳統原文不得改寫，免責文字本就該恆真。

## 機器可驗證規則對照表

| 規則 | 檢查方式 | 是否已實作 |
|---|---|---|
| R1 禁「您」 | 字串比對 | ✅ |
| R2 未來斷言 | 斷言詞比對 | ✅ |
| R3 段落 ≤ 3 句 | 切句計數 | ✅ |
| R4 限定詞 ≤ 1 | 五詞合計計數 | ✅ |
| R5 具體性 | **無法純靜態判定**，改以「出現率」代理：同一句在越多命盤中出現，越可能是通用句 | ✅（間接） |
| R6 邊界 | 免責欄位存在性檢查 | ✅ |
| R7 對沖語 | 句型標記比對 | ✅ |
| R8 自我說明 | 標記比對 | ✅ |
| R9 書面語 | 標記比對（附例外清單） | ✅ |
| 核心判準 | 出現率 > 30% 判為 `OVER_GENERIC` | ✅ |

R5 的具體性無法用正則判斷，因此工具改用**出現率**作為代理指標：一句話如果在 500 組差異極大的命盤中有超過 30% 都出現，它幾乎不可能是在描述某個特定的人。這正是核心判準的可計算版本。

### 為什麼需要 R7–R9 這一軸

出現率只量一件事：句子夠不夠「不通用」。文案為了通過這個檢查，會往「多引用一點命盤數據」走——結果是**具體了，但更像資料表**。實際回饋正是「用字遣詞還是太資料感、不夠口語化」，而舊的量測完全看不到這個問題（它甚至會獎勵這種寫法）。

所以 R7–R9 是第二個軸，和出現率互相獨立：出現率問「這句話是在講誰」，口語度問「這句話像不像人說的」。兩個都過才算合格。

### 定義句與出現率的張力

還有第三種情況，兩個軸都處理不了：**為了讓術語看得懂而寫的定義句**。

```
太陽在摩羯座，講的是你想成為什麼樣的人
命宮是你本來的樣子，身宮是後天長成的樣子
```

「講的是你想成為什麼樣的人」對每個人都成立——但那是**定義的本質**，不是巴納姆句。它沒有宣稱這個人如何，只說明那個位置在講什麼；真正的解讀在後面逐顆行星、逐個宮位的卡片裡。

出現率量不出這個差別，所以只能靠人判斷。做法是：**定義句允許存在，但必須緊接著具體內容**，不能只有定義。如果一段文字從頭到尾都在解釋術語、沒有一句在講這個人，那不是定義句的問題，是那一段根本沒有解讀。
